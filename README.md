# WasteAI: AI Waste Segregation System

Live site: https://wasteai.duckdns.org/

Take or upload a photo of a waste item and get the waste category, the right bin, and clear disposal steps. Arabic (RTL) and English, light and dark themes, works on phones, tablets and desktops.

> **This is a guidance tool, not a legal authority.** Hazardous and medical waste always carry a "check your local authorities" note.

## Features
- Camera capture or photo upload (drag and drop supported)
- 26 categories: plastics by resin code, paper, glass, metals, organic, e-waste, batteries, textiles, hazardous, medical, and more
- Honest confidence: High / Medium / Not sure, with two alternatives when unsure
- "Why?" panel showing the labels from each source, translated through a static dictionary (no live translation)
- "This is wrong?" feedback with a full category picker, to improve the rules
- Browse: category library with search and group filters, deep-linkable (`#/browse?group=glass&q=bottle`)
- 100% Arabic UI in Arabic and 100% English UI in English; only resin codes and file formats (PET, HDPE, JPEG, PNG, WebP, MB ...) stay in Latin, wrapped in `<bdi dir="ltr">`
- Calm optional sound design (synthesized in the browser, no audio files)
- Accessible: WCAG AA contrast, keyboard navigation, reduced-motion support
- Resilient: rate-limit countdown on 429, retry with backoff for category loading, global error panel, client errors sent to the server log
- Private: photos are never stored; buffers are deleted right after analysis

## How it works
```
Browser -> Nginx (HTTPS) -> FastAPI -> local ONNX model + Azure AI Vision (+ optional ReciclAPI)
                                    -> rule-based mapper -> aggregator -> localized result
```
No generative AI is used for classification. Labels from the sources are mapped to our categories with transparent JSON rules (`server/data/label_rules/`), then combined (0.6 local + 0.4 Azure, renormalized over the sources that answered). See `docs/ARCHITECTURE.md`.

- **Local model:** `emilyyy04/trash_classifier`, converted to ONNX (D-011), 10 labels: battery, cardboard, clothes, glass, metal, organic, paper, plastic, shoes, trash. Chosen by our own photo evaluation, not by published accuracy (D-009).
- **Azure AI Vision F0:** free tier, quota counter stops at 4,800 calls a month.
- **Hazard categories** (battery, hazardous chemical, medical, e-waste) show warnings from confidence 0.35.
- **Edge protection:** Nginx rate limit (10 per minute on `/classify`), security headers on every location, JSON error for oversize uploads (3 MB cap).

## Quick start (development)
```bash
git clone https://github.com/<OWNER>/WasteAI.git && cd WasteAI
# Server
cd server && python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env        # set MODEL_PATH, optional AZURE_VISION_ENDPOINT and AZURE_VISION_KEY
uvicorn app.main:app --port 8100 --workers 1 --proxy-headers
# Frontend (no build step), in a second terminal
cd frontend && python3 -m http.server 8000
```
Open `http://localhost:8000`. The camera needs HTTPS or `localhost`. Until the server runs, add `?mock=1` to the URL to use `frontend/mock/` data (`?mock=1&scenario=uncertain|hazard|rate_limited|image_too_large|all_sources_failed`).

Tests and checks (run from the repo root unless noted):
```bash
cd server && pytest -q && ruff check . && cd ..
bash scripts/check_lines.sh          # every file under 500 lines
python3 scripts/check_paths.py       # line 1 of every file names its own path
python3 content/tools/check_content.py   # ar/en parity, allow-list, label coverage
bash scripts/parity_check.sh         # local vs server parity (read-only)
```

## Deployment
One idempotent script for an Ubuntu 24.04 server: `bash deploy/install.sh --domain <DOMAIN> --email <EMAIL>`. Flags: `--status`, `--rollback`, `--fix-owner`, `--stop-containers`. It never restarts nginx, docker or other projects' services. Re-run it after every `git pull` to sync the app copy. Details: `docs/DEPLOYMENT.md`.

Live deployment: https://wasteai.duckdns.org/ (systemd unit `wasteai.service`, uvicorn on `127.0.0.1:8100`, Nginx and Certbot in front).

## API
Base path `/api/v1`: `GET /health`, `GET /categories?lang=ar|en`, `POST /classify?lang=ar|en` (multipart `image`, jpeg/png/webp up to 2 MB), `POST /feedback`, `POST /log` (client errors, rate limited). Contract: `contract/openapi.yaml`.

## Configuration
| Variable | Purpose |
|---|---|
| `MODEL_PATH` | Local ONNX model file |
| `MODEL_LABELS_PATH` | Label set file (default `server/data/model_labels.json`) |
| `AZURE_VISION_ENDPOINT`, `AZURE_VISION_KEY` | Azure AI Vision (free F0 tier); disabled if empty |
| `RECICLAPI_KEY` | Optional third source; off by default |
| `MODEL_URL`, `MODEL_SHA256` | Used by the installer to download and verify the model |
| `LOG_LEVEL` | Server log level (default INFO), logs are JSON on stdout |

Secrets live only in `.env` (git-ignored).

## Privacy
Images are processed in memory and discarded. Only the result JSON is cached (7 days, keyed by image hash). Feedback stores the request ID and the chosen category, and only for a request ID the server issued. Server logs hold no IP address, no image and no raw labels. No accounts, no tracking.
